================================================================================
Genre Import Tool（ジャンル別インポートツール） 設計書
バージョン: 1.0
実装ファイル: GenreImportTool.cs（単一ファイル）
名前空間: YuukaTools.GenreImport
================================================================================

--------------------------------------------------------------------------------
1. 文書の目的と設計方針
--------------------------------------------------------------------------------
本書は、要件定義書（requirements-genre-import-tool.txt）に
基づく Genre Import Tool v1.0 の設計を記録するものです。
クラス構成、データ、画面、処理フロー、例外処理、配布形式を
実装（GenreImportTool.cs）と一致する形で記述します。

設計方針:
  方針 1: 自動判定をしない。ジャンル決定は常に利用者の操作とする。
  方針 2: 単一ファイルで完結させ、導入コストを最小にする。
  方針 3: 移動は AssetDatabase 経由に限定し、GUID を保持する。
  方針 4: 破壊的な操作の前に必ず確認を挟み、上書きをしない。
  方針 5: Unity の仕様でできないこと（.unitypackage の直接展開、
          インポート前の停止）は、代替フローで吸収し、利用者に
          隠さず明示する。

--------------------------------------------------------------------------------
2. システム構成
--------------------------------------------------------------------------------
本ツールは Unity Editor 内でのみ動作する Editor 拡張である。
実行時（ビルド後のアプリ）には含まれない。

構成要素:
  ・Unity Editor（2020.3 以降を目安）
  ・GenreImportTool.cs（Assets/Editor/ に配置）
  ・GenreImportSettings.asset（設定保存用 ScriptableObject、
    Assets/Editor/ に自動生成）
  ・Unity 標準 API: AssetDatabase、EditorWindow、
    AssetPostprocessor、EditorUtility、EditorApplication

外部依存: なし。追加ライブラリ、ネットワーク通信は使用しない。

--------------------------------------------------------------------------------
3. クラス設計
--------------------------------------------------------------------------------
名前空間 YuukaTools.GenreImport の中に 5 つの型を置く。

■ 3-1. GenreImportSettings（ScriptableObject）
  役割: 設定と状態の永続化を担う唯一のデータクラス。
  主なメンバー:
    ・定数 SettingsPath = "Assets/Editor/GenreImportSettings.asset"
    ・定数 DefaultSortedRoot = "Assets/Sorted"
    ・List<string> genres          ジャンル一覧
    ・List<string> pendingFolders  保留フォルダ一覧
    ・List<string> ignoredFolders  無視フォルダ一覧
    ・string sortedRoot            整理ルート
    ・bool autoPromptOnImport      確認画面の自動表示（既定 true）
    ・static string[] DefaultGenres  既定ジャンル 8 件
    ・static string[] SystemFolders  常時除外するフォルダ 6 件
    ・static GetOrCreate()  設定の取得。なければフォルダと
      アセットを生成し、既定ジャンルで初期化する。生成した
      インスタンスは静的フィールド _instance に保持する。
    ・Save()  EditorUtility.SetDirty と AssetDatabase.SaveAssets
      で変更を保存する。
    ・GenreFolder(genre)  整理ルートとサニタイズ済みジャンル名
      からジャンルフォルダのパスを返す。
    ・SanitizeFolderName(name)  静的メソッド。空白のみの場合は
      「未分類」を返し、前後の空白除去、ファイル名に使えない
      文字と / と \ を _ に置換する。
    ・EnsureGenreFolder(genre)  整理ルートとジャンルフォルダが
      なければ AssetDatabase.CreateFolder で作成する。
    ・EnsureFolder(assetPath)  静的メソッド。パスを / で分割し、
      上位から順に不足フォルダを作成する。

■ 3-2. GenreMover（static クラス）
  役割: 移動と外部取り込みの共通ロジック。両ウィンドウから使う。
  主なメンバー:
    ・static bool IsBusy  自分自身の移動／コピー中であることを
      示すフラグ。検出側（AssetPostprocessor）はこれが true の
      間は何もしない。
    ・MoveFolderToGenre(sourceFolder, genre, showConfirm = true)
      移動元フォルダの存在確認 → ジャンルフォルダ確保 →
      移動先決定（UniqueDestination）→ 確認ダイアログ →
      IsBusy を立てて AssetDatabase.MoveAsset を実行 →
      失敗時は理由を表示、成功時は保留から除去、保存、Refresh、
      Console ログ出力。戻り値は成否（bool）。
    ・UniqueDestination(dest)  移動先が空いていればそのまま、
      使用中なら _1 から _99 まで順に試し、最後は GUID 先頭
      6 文字を付けた名前を返す（private）。
    ・CopyExternalFolder(externalFolder, genre)
      外部フォルダをジャンルフォルダ配下へコピーする。
      フォルダ名はサニタイズし、同名時は連番で回避する。
      IsBusy を立て、CopyDirectory で再帰コピーした後 Refresh。
    ・CopyExternalFiles(externalFiles, genre)
      外部ファイル群をジャンルフォルダ直下へコピーする。
      ファイル名はサニタイズする。上書きはしない
      （File.Copy の第 3 引数は false）。
    ・ToFullPath(assetPath)  アセットパスを、プロジェクトルート
      基準の OS フルパスへ変換する。
    ・CopyDirectory(src, dest)  再帰コピー（private）。
      .meta ファイルは除外し、ドットで始まるフォルダは除外する。

■ 3-3. GenreImportWindow（EditorWindow）
  役割: メイン画面。メニュー Tools/ジャンル別インポート で開く。
  ウィンドウ最小サイズ: 520 x 560。タイトル: ジャンル別インポート。
  状態:
    ・GenreImportSettings _s
    ・Vector2 _scroll（スクロール位置）
    ・string _newGenre（追加用入力）
    ・int _importGenreIndex（インポート対象ジャンルの選択位置）
    ・Dictionary<string, int> _pendingGenreIndex
      （保留フォルダごとの選択位置）
    ・Dictionary<int, string> _renameBuffer
      （行ごとの名前変更用入力バッファ）
  処理:
    ・OnEnable で設定を取得する。
    ・OnGUI はスクロールビュー内に案内 HelpBox を出し、
      次の 4 区分を上から描画する。
        DrawSettings()     設定区分
        DrawGenreManager() ジャンル管理区分
        DrawImporter()     インポート区分
        DrawPending()      保留区分
      各区分の詳細は第 5 章（画面設計）を参照。

■ 3-4. GenreAssignmentPrompt（EditorWindow）
  役割: 直接ドラッグ直後に自動で開く、ジャンル割り当て確認画面。
  ウィンドウ最小サイズ: 480 x 300。タイトル: ジャンルの割り当て。
  状態:
    ・GenreImportSettings _s
    ・int _genreIndex（選択中ジャンル）
    ・string _newGenre（その場で作るジャンル名）
  処理:
    ・static OpenIfPending()  実在しない保留を掃除し、保留が
      なければ何もしない。あればウィンドウを開いてフォーカスする。
    ・OnGUI は保留の先頭 1 件だけを対象として表示する。
      残件数は「ほか保留 N 件」と表示する。
      ジャンル選択、新規ジャンル作成（作成して使う）、
      ［このジャンルへ移動する］、［そのまま置く（今後検出しない）］、
      ［後で決める］を提供する。
      移動成功後、または無視／後で決めるで保留が空になったら
      ウィンドウを閉じる。後で決める場合は保留に残したまま閉じる。

■ 3-5. GenreAssetPostprocessor（AssetPostprocessor）
  役割: インポート完了の通知を受け、未分類フォルダを検出する。
  処理:
    ・static OnPostprocessAllAssets(importedAssets, deletedAssets,
      movedAssets, movedFromAssetPaths)
      引数のうち主に importedAssets を走査する。
      GenreMover.IsBusy が true なら即座に戻る。
      設定取得に失敗した場合は例外を捕捉し、静かに終了する。
    ・GetUnclassifiedTopFolder(path, settings)  判定本体（private）。
      第 4 章の検出ルールに従い、対象ならトップフォルダを、
      対象外なら null を返す。
    ・新規検出時は保留へ追加、重複と無視リストとシステム
      フォルダを除外し、変更があれば保存する。
      autoPromptOnImport が有効な場合は EditorApplication.delayCall
      に登録し、次フレームで GenreAssignmentPrompt.OpenIfPending()
      を呼ぶ（インポート処理中のウィンドウ表示を避けるため）。

--------------------------------------------------------------------------------
4. データ設計
--------------------------------------------------------------------------------
■ 保存先
  Assets/Editor/GenreImportSettings.asset
  （ScriptableObject として Unity のアセット形式で保存される）

■ 保存項目
  項目              型            既定値              用途
  genres            List<string>  既定 8 件           ジャンル一覧
  pendingFolders    List<string>  空                  保留パス一覧
  ignoredFolders    List<string>  空                  無視パス一覧
  sortedRoot        string        Assets/Sorted       整理ルート
  autoPromptOnImport bool         true                自動表示の可否

  ※ パスはすべて Assets から始まるアセットパス形式で保持する。
  ※ ジャンル名は表示名として保持し、フォルダ化の時点で
     SanitizeFolderName を通す。

■ 既定ジャンル（DefaultGenres、順序固定）
  アバター / 3Dモデル / 衣装 / ギミック / シェーダー /
  アニメーション / テクスチャ・マテリアル / ツール・スクリプト

■ 常時除外フォルダ（SystemFolders）
  Assets/Editor / Assets/Plugins / Assets/Gizmos /
  Assets/Resources / Assets/StreamingAssets / Assets/WebGLTemplates

■ フォルダ設計
  Assets/
    Sorted/                  整理ルート（sortedRoot で変更可）
      <ジャンル名>/           ジャンルフォルダ
        <取り込んだフォルダやファイル>
    Editor/
      GenreImportTool.cs
      GenreImportSettings.asset

■ 検出ルール（GetUnclassifiedTopFolder）
  次のすべてを満たす場合のみトップフォルダを返す。
    1. パスが Assets/ で始まる。
    2. 整理ルート配下ではない。
    3. Assets/Editor/ 配下ではない。設定ファイル自身ではない。
    4. パスを / で分割し、2 要素目をトップとする。
       2 要素目が Imported で 3 要素以上ある場合は
       Assets/Imported/<3 要素目> を 1 単位とする。
    5. トップが整理ルートそのものではない。
    6. 実在するフォルダである。ただしフォルダ自体の通知が
       まだ来ていない場合は、3 要素以上のパスであれば
       親として扱い対象とする。
  上記に当たらない、Assets 直下の単体ファイル等は null（対象外）。

5. 画面設計
--------------------------------------------------------------------------------
■ 5-1. メインウィンドウ（GenreImportWindow）
  構成（上から順、全体をスクロール可能とする）:
    ・見出し「ジャンル別インポート」
    ・HelpBox: 自動判定をしない旨、保留の説明
    ・区分「設定」
        整理ルート（テキスト入力、変更時に保存）
        インポート時に確認画面を自動で開く（トグル、変更時に保存）
    ・区分「ジャンル管理（N 件）」
        行ごと: 名前入力欄、［名前を変更］［フォルダ作成］
                ［開く］［削除］
        新規行: 新しいジャンル名、［ジャンルを追加］
        ［全ジャンルのフォルダを作成］
    ・区分「インポート（ジャンルを選んでから入れる）」
        対象ジャンル（プルダウン）、取り込み先パスの表示
        ［ファイルを選んでインポート］
        ［フォルダを選んでインポート］
        ［.unitypackage をインポート］
        HelpBox: 複数ファイルはフォルダ経由が確実である旨
        ※ ジャンルが 0 件の場合は警告 HelpBox を出して中断する。
    ・区分「保留 ― 未分類フォルダ（N 件）」
        保留 0 件時: 「保留はありません」の文言
        保留 1 件ごと（枠付き）:
          フォルダパス（太字）、ジャンル（プルダウン）、
          ［このジャンルへ移動］［そのまま置く］［後で決める］
        ［無視リストをリセット（再検出できるようにする）］
        無視中フォルダの一覧表示（ある場合のみ）

■ 5-2. 割り当て確認ウィンドウ（GenreAssignmentPrompt）
  構成:
    ・見出し「新しいフォルダがインポートされました」
    ・HelpBox: 移動で GUID が保持される旨
    ・対象フォルダの表示、残件数の表示
    ・ジャンル（プルダウン）
    ・新しいジャンルを作る（入力欄）＋［作成して使う］
    ・［このジャンルへ移動する］（高さ 30 の主ボタン）
    ・［そのまま置く（今後検出しない）］［後で決める］

■ 5-3. ダイアログ
  すべて EditorUtility.DisplayDialog を使用する。
    ・移動の確認: 移動元、移動先、決め打ち破損の注意、
      ボタンは［移動する］［キャンセル］
    ・移動元の不存在、移動失敗、インポート失敗: 理由を表示し
      ボタンは［OK］
    ・ジャンル削除の確認: フォルダは消えない旨を表示
    ・そのまま置くの確認: 無視リスト入りの旨を表示
    ・.unitypackage 実行前の注意: 元パス展開と保留検出の流れを
      表示し、ボタンは［理解してインポートする］
    ・同名ジャンル追加時: 既に存在する旨を表示

■ 5-4. ファイル／フォルダ選択
  ・ファイル: EditorUtility.OpenFilePanel
  ・フォルダ: EditorUtility.OpenFolderPanel
  ・.unitypackage: EditorUtility.OpenFilePanelWithFilters
    （フィルタは "Unity Package", "unitypackage"）
  ・.unitypackage の実行は AssetDatabase.ImportPackage(path, true)
    とし、第 2 引数により Unity 標準のインポート確認画面を出す。

6. 処理フロー設計
--------------------------------------------------------------------------------
■ 6-1. 初回起動
  メニュー選択 → GenreImportSettings.GetOrCreate()
  → 設定がなければ Assets/Editor を確保し、アセットを生成、
    既定ジャンル 8 件で初期化して保存 → ウィンドウ表示。

■ 6-2. ファイル／フォルダのインポート
  ジャンル選択 → 取り込み先表示 → 選択ダイアログ →
  GenreMover のコピー処理（IsBusy = true → コピー → false）→
  AssetDatabase.Refresh → ログ出力。
  コピー中のインポート通知は IsBusy により検出対象にならない。

■ 6-3. .unitypackage のインポート
  ファイル選択 → 注意ダイアログ → AssetDatabase.ImportPackage →
  Unity が元パスへ展開 → AssetPostprocessor が新規トップ
  フォルダを保留に追加 → 設定に応じて確認画面を次フレームで
  表示 → 利用者がジャンルへ移動（6-5 と同じ）。

■ 6-4. 直接ドラッグ時の検出
  Project へドロップ → Unity がインポート →
  OnPostprocessAllAssets が importedAssets を走査 →
  GetUnclassifiedTopFolder で判定 → 重複／無視／システム
  フォルダを除外 → 保留へ追加して保存 → delayCall で
  確認画面を開く（autoPromptOnImport が true の場合のみ）。

■ 6-5. フォルダのジャンル移動
  移動要求 → 移動元存在確認 → ジャンルフォルダ確保 →
  UniqueDestination で移動先決定 → 確認ダイアログ →
  キャンセルなら終了（何も動かさない）→ IsBusy を立てて
  AssetDatabase.MoveAsset → 空文字列でない戻り値はエラーとして
  表示 → 成功時は保留から除去、保存、Refresh、ログ出力。

■ 6-6. そのまま置く／後で決める
  そのまま置く: 確認後、保留から除去し無視リストへ追加、保存。
  後で決める: データを変更せず、保留のまま残す。

--------------------------------------------------------------------------------
7. 例外処理・安全設計
--------------------------------------------------------------------------------
  ・移動元の不存在: ダイアログでパスを示して中断する。
  ・移動失敗: MoveAsset の戻り文字列（理由）と移動元／移動先を
    ダイアログ表示する。保留からは除去しない。
  ・コピー失敗: 例外を捕捉し、例外メッセージをダイアログ表示
    する。IsBusy は finally で必ず解除する。
  ・同名回避: フォルダ移動とフォルダ取り込みは
    UniqueDestination で連番化する。ファイルコピーは
    上書きしない設定とし、失敗はダイアログで知らせる。
  ・ジャンル名の安全性: SanitizeFolderName で、ファイル名に
    使えない文字と区切り文字を _ に置換する。空白のみは
    「未分類」とする。
  ・ジャンル名変更の安全性: 既存フォルダを自動リネームしない。
    フォルダのリネームは利用者が Project ウィンドウで
    Unity 経由で行う運用とし、GUID 保持を担保する。
  ・ジャンル削除の安全性: 一覧からの削除のみとし、実フォルダと
    中身は削除しない。実行前に確認する。
  ・自己検出の防止: 移動／コピー中は IsBusy により
    AssetPostprocessor を無効化する。
  ・設定生成中の検出: インポート処理中に設定取得が例外と
    なった場合は捕捉して静かに終了し、処理を壊さない。
  ・消えた保留の掃除: ウィンドウ表示時と確認画面表示時に、
    実在しないフォルダを保留から RemoveAll で除去する。

--------------------------------------------------------------------------------
8. ログ設計
--------------------------------------------------------------------------------
  Console ログの接頭辞は [GenreImport] とする。
    ・移動成功: [GenreImport] 移動しました: <元> -> <先>
    ・フォルダ取り込み: [GenreImport] フォルダを取り込みました: <先>
    ・未分類検出: [GenreImport] 未分類フォルダを検出しました: <パス>

--------------------------------------------------------------------------------
9. 配布形式の設計
--------------------------------------------------------------------------------
  形式 1: GenreImportTool.cs 単体
    配置先は Assets/Editor/GenreImportTool.cs とする。

  形式 2: GenreImportTool.unitypackage
    .unitypackage は gzip 圧縮された tar 形式であり、
    GUID フォルダ配下に次の 3 点を格納する。
      <GUID>/asset       … GenreImportTool.cs の内容そのもの
      <GUID>/asset.meta  … MonoImporter 形式のメタ情報
      <GUID>/pathname    … "Assets/Editor/GenreImportTool.cs"
    GUID は内容から決定的に定まる 32 桁の 16 進文字列を用いる。
    配布時の検証では、展開した asset が元の .cs と完全一致
    することまで確認する。

10. テスト観点（受け入れ確認用）
--------------------------------------------------------------------------------
  ・導入: .cs 配置と .unitypackage の両経路でコンパイルが
    通り、メニューが表示されること。
  ・初期化: 設定ファイルと既定ジャンル 8 件が生成されること。
  ・ジャンル管理: 追加、重複拒否、名前変更、削除（フォルダが
    残ること）、一括フォルダ作成。
  ・取り込み: ファイル 1 件、フォルダ（.meta 除外、ドット
    フォルダ除外）、同名時の連番化。
  ・.unitypackage: 元パス展開、保留検出、ジャンル移動まで。
  ・検出: Assets 直下と Assets/Imported 直下の新規フォルダ、
    単体ファイルが対象外であること、システムフォルダと
    整理済み配下が対象外であること、自己処理中に検出しないこと。
  ・移動: 確認とキャンセル、GUID 保持、同名回避、失敗表示。
  ・保留と無視: そのまま置く、後で決める、リセット後の再検出。
  ・永続化: Unity 再起動後に設定が保持されること。
  ・自動表示 OFF: 検出はされるが確認画面が開かないこと。

  ※ 作成環境に Unity がなかったため、本書のテスト観点は
     配布時点では実機未実施である。導入後に上記観点で
     確認することを前提とする。

--------------------------------------------------------------------------------
11. 今後の拡張候補（v1.0 対象外）
--------------------------------------------------------------------------------
  次は要件の対象外であり、必要になった場合に別途設計する。
    ・複数ファイル選択による一括取り込みの強化
    ・ジャンルごとの件数表示などの集計
    ・設定のエクスポート／インポート
  自動判定による分類は、設計方針 1 により今後も採用しない。
