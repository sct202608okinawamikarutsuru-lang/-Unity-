================================================================================
Genre Import Tool（ジャンル別インポートツール） 要件定義書
バージョン: 1.0
対象ツール: GenreImportTool.cs（Unity Editor 拡張、単一ファイル）
================================================================================

--------------------------------------------------------------------------------
1. 文書の目的
--------------------------------------------------------------------------------
本書は、Unity プロジェクト向けジャンル別インポートツール
「Genre Import Tool」の要件を定義するものです。
実装済みの v1.0 が満たすべき目的、対象範囲、機能要件、
非機能要件、制約、対象外事項、受け入れ条件を明確にし、
利用者・開発者・今後の改修担当者の間で認識をそろえることを
目的とします。

関連文書:
  ・README     : readme-genre-import-tool.txt
  ・設計書     : design-genre-import-tool.txt

--------------------------------------------------------------------------------
2. 背景と課題
--------------------------------------------------------------------------------
利用者は Unity で作業し、アセット、3Dモデル、ギミック、衣装などを
日常的にプロジェクトへインポートしている。

課題は次のとおりである。

  課題 1: アセットの種類が増えるほど、Assets 直下が煩雑になり、
          目的のアセットを探す時間が増える。
  課題 2: インポート直後に整理せず後回しにすると、未整理の
          フォルダが蓄積し、後からの仕分け負担が大きくなる。
  課題 3: ファイルを OS 上で直接移動すると GUID や参照が壊れる
          危険があり、安全な移動手段が必要である。
  課題 4: 拡張子や名前による自動判定は、衣装／3Dモデル／
          ギミック等の境界で誤判定しやすく、信頼できない。

--------------------------------------------------------------------------------
3. 目的・目標
--------------------------------------------------------------------------------
目的:
  インポートの時点で、利用者自身がジャンルを 1 つ選択し、
  そのジャンルのフォルダへアセットを入れる仕組みを提供する。
  あわせて、通常のドラッグ＆ドロップで入れたフォルダについても、
  未分類として検出して後から同じ仕分けができるようにする。

目標:
  ・誤判定による誤分類を起こさない（自動判定を行わない）。
  ・移動しても GUID と参照が保持される。
  ・移動前に内容を確認でき、取り消しができる。
  ・導入はファイル 1 つの配置、または .unitypackage 1 回の
    インポートで完了する。
  ・既定ジャンルだけでもすぐに使い始められる。

--------------------------------------------------------------------------------
4. 利用者と利用場面
--------------------------------------------------------------------------------
主な利用者:
  Unity でアセット、3Dモデル、衣装、ギミック等を扱う制作者本人。
  個人プロジェクトでの利用を主対象とする。

利用場面:
  ・BOOTH 等で入手したアセットをプロジェクトへ入れるとき
  ・.unitypackage を展開するとき
  ・外部のファイル／フォルダをプロジェクトへ取り込むとき
  ・直接ドラッグで入れてしまったフォルダを後から整理するとき

--------------------------------------------------------------------------------
5. 対象範囲
--------------------------------------------------------------------------------
対象に含む:
  ・Unity Editor 上で動作する整理ツール本体
  ・ジャンルの管理、インポート、保留処理、設定の保存
  ・Assets 配下のフォルダ単位の移動

対象に含まない（対象外は第 9 章にも明記）:
  ・ビルド後のゲーム／アプリ本体への組み込み
    （本ツールは Editor 専用である）
  ・Assets 以外のファイルシステム全体の整理
  ・単体ファイル単位での自動仕分け

--------------------------------------------------------------------------------
6. 用語定義
--------------------------------------------------------------------------------
  ジャンル      : アセットの分類名。例: アバター、衣装。
  整理ルート    : ジャンルフォルダをまとめる親フォルダ。
                  既定は Assets/Sorted。
  ジャンルフォルダ: 整理ルート直下の、ジャンル名のフォルダ。
                  例: Assets/Sorted/衣装/
  保留          : インポートされたが、まだジャンルが決まって
                  いないトップフォルダの状態、およびその一覧。
  無視リスト    : 「そのまま置く」と判断され、今後は検出対象に
                  しないフォルダの一覧。
  トップフォルダ: 検出単位となる最上位のフォルダ。
                  Assets/<Folder>、または
                  Assets/Imported/<Folder> を指す。
  GUID          : Unity がアセットを識別する ID。参照の保持には
                  .meta とあわせて維持されることが重要である。

--------------------------------------------------------------------------------
7. 機能要件
--------------------------------------------------------------------------------
優先度: 必須 = v1.0 で提供する。対象外 = 意図的に提供しない。

[FR-01 ジャンル管理] 必須
  ・既定ジャンル 8 件を用意すること。
    アバター、3Dモデル、衣装、ギミック、シェーダー、
    アニメーション、テクスチャ・マテリアル、ツール・スクリプト。
  ・ジャンルの追加ができること。同名は追加できないこと。
    追加時に対応するジャンルフォルダを作成すること。
  ・ジャンルの名前変更ができること。ただし既存フォルダの
    自動リネームは行わないこと（安全のため）。
  ・ジャンルを一覧から削除できること。確認を求めること。
    フォルダと中身は削除しないこと。
  ・各ジャンルのフォルダ作成と、Project ウィンドウでの表示が
    できること。全ジャンルのフォルダ一括作成ができること。

[FR-02 ツール画面からのインポート] 必須
  ・対象ジャンルをプルダウンで選択でき、取り込み先パスを
    画面に表示すること。
  ・外部ファイルを 1 件選んで、ジャンルフォルダ直下へ
    コピーできること。
  ・外部フォルダを選んで、ジャンルフォルダ配下へ丸ごと
    コピーできること。.meta はコピーせず、ドットで始まる
    フォルダは除外すること。
  ・.unitypackage を選んで Unity 標準インポートを実行できる
    こと。実行前に「元のパスへ展開される」旨を知らせること。

[FR-03 直接インポートの検出と割り当て] 必須
  ・Assets 直下、および Assets/Imported 直下に新しくできた
    トップフォルダを検出し、保留に追加すること。
  ・検出時に、設定が有効ならジャンル割り当て確認画面を
    自動で開くこと。開くタイミングはインポート処理と
    競合しないよう次フレームとすること。
  ・確認画面では、ジャンル選択、その場でのジャンル新規作成、
    移動、そのまま置く、後で決める、が選べること。
    保留が複数ある場合は 1 件ずつ順に処理できること。
  ・ツール自身の移動／コピー処理中は検出を止めること
    （自己検出の防止）。

[FR-04 保留の処理] 必須
  ・メインウィンドウに保留一覧と件数を表示すること。
    保留がない場合はその旨を表示すること。
  ・保留ごとにジャンルを選んで移動できること。
  ・「そのまま置く」では確認のうえ無視リストへ入れ、
    以後検出しないこと。「後で決める」では保留のまま残すこと。
  ・実在しないフォルダは保留から自動で除去すること。
  ・無視リストをリセットし、再検出できるようにすること。
    無視中のフォルダは画面に表示すること。

[FR-05 安全な移動] 必須
  ・フォルダ移動は AssetDatabase.MoveAsset で行い、
    GUID と参照を保持すること。OS 上で直接移動しないこと。
  ・移動前に移動元と移動先を示す確認ダイアログを出し、
    キャンセル可能とすること。パス決め打ちによる破損の
    可能性もあわせて知らせること。
  ・移動先に同名がある場合は上書きせず、連番（_1、_2 …）を
    付けた別名を使うこと。
  ・移動に失敗した場合は、理由と移動元／移動先を表示すること。

[FR-06 設定の保存] 必須
  ・ジャンル一覧、保留リスト、無視リスト、整理ルート、
    自動表示の ON／OFF を ScriptableObject
    （Assets/Editor/GenreImportSettings.asset）に保存し、
    Unity を開き直しても保持されること。
  ・設定ファイルがない場合は初回に自動生成し、既定ジャンルで
    初期化すること。
  ・整理ルートは変更可能とし、空欄にはできないこと。

[FR-07 除外規則] 必須
  ・整理ルート配下、Assets/Editor 配下、設定ファイル自身は
    検出対象にしないこと。
  ・システム系フォルダ（Assets/Editor、Assets/Plugins、
    Assets/Gizmos、Assets/Resources、Assets/StreamingAssets、
    Assets/WebGLTemplates）は検出対象にしないこと。
  ・Assets 直下の単体ファイルは検出対象にしないこと。

--------------------------------------------------------------------------------
8. 非機能要件
--------------------------------------------------------------------------------
[NFR-01 導入の容易さ]
  本体は単一ファイル GenreImportTool.cs とし、
  Assets/Editor/ への配置、または .unitypackage の
  インポートだけで導入できること。追加の外部ライブラリを
  必要としないこと。

[NFR-02 対応環境]
  Unity 2020.3 以降を目安とすること。使用 API はそれ以前から
  あるものが中心であること。URP／HDRP、VRChat SDK 等と
  競合しないこと。

[NFR-03 安全性・可逆性]
  移動前の確認を必須とし、利用者の明示的な操作なしに
  フォルダを移動しないこと。ジャンル削除で実フォルダを
  削除しないこと。同名時の上書きをしないこと。

[NFR-04 使いやすさ]
  メニューは Tools > ジャンル別インポート の 1 か所とし、
  メインウィンドウ内に設定、ジャンル管理、インポート、保留を
  まとめること。各処理の結果や失敗理由をダイアログまたは
  Console ログ（接頭辞 [GenreImport]）で知らせること。

[NFR-05 保守性]
  名前空間 YuukaTools.GenreImport にまとめ、設定、移動、
  メイン画面、割り当て画面、検出をクラス単位で分けること
  （詳細は設計書を参照）。

--------------------------------------------------------------------------------
9. 制約と対象外事項
--------------------------------------------------------------------------------
制約:
  ・.unitypackage は Unity の仕様上、記録された元のパスへ
    展開される。任意フォルダへ直接展開する公式 API がないため、
    「展開 → 保留検出 → ジャンルへ移動」の 2 段階とする。
  ・Unity にはインポート前に処理を止めて入力を求める標準的な
    仕組みがないため、直接ドラッグ時はインポート直後の検出で
    代替する。
  ・パスを文字列で決め打ちしたアセットは、GUID が保持されても
    移動で壊れる可能性がある。これは利用者への注意喚起と
    「そのまま置く」選択肢で対処し、ツール側では防げない。

対象外（意図的に実装しない）:
  ・拡張子やフォルダ名によるジャンルの自動判定・自動分類
    （利用者の明示的な要望により対象外）
  ・アセットの内容解析、サムネイル生成、検索・絞り込み、
    件数や容量の集計ダッシュボード
  ・単体ファイル単位の検出と仕分け
  ・ジャンルフォルダ自体の自動リネーム
  ・ネットワーク連携、クラウド保存、複数プロジェクト間の
    設定同期

--------------------------------------------------------------------------------
10. 受け入れ条件
--------------------------------------------------------------------------------
次のすべてを確認できれば、v1.0 の要件を満たすものとする。

  1. 空のプロジェクトに .cs 配置／.unitypackage 導入の
     いずれでも、エラーなく Tools > ジャンル別インポート が
     開けること。
  2. 初回起動で既定ジャンル 8 件と設定ファイルが生成され、
     ジャンル追加で Assets/Sorted/<ジャンル>/ が作れること。
  3. ツール画面からファイル／フォルダを取り込むと、選んだ
     ジャンルのフォルダへ入ること。
  4. .unitypackage を取り込むと元のパスへ展開され、新規
     フォルダが保留に検出されること。
  5. Project へフォルダを直接ドラッグすると保留に追加され、
     確認画面（設定 ON 時）または保留欄からジャンルへ
     移動できること。
  6. 移動時に確認ダイアログが出て、キャンセルで何も
     動かないこと。移動後は GUID が保持されること。
  7. 同名フォルダがある場合に上書きされず、連番付きに
     なること。
  8. 「そのまま置く」で無視リストに入り再検出されず、
     リセットで再検出可能になること。
  9. Unity を開き直しても、ジャンル、保留、無視リスト、
     整理ルート、自動表示設定が保持されること。

  ※ 作成環境に Unity がなかったため、上記は配布時点では
     実機未検証の受け入れ項目である。導入後の初回確認で
     順にチェックすること。

--------------------------------------------------------------------------------
11. 前提とリスク
--------------------------------------------------------------------------------
前提:
  ・利用者は Unity Editor の基本操作（Project ウィンドウ、
    メニュー、パッケージインポート）ができること。
  ・プロジェクトのバックアップまたはバージョン管理が
    利用者側で用意されていることが望ましい。

リスクと対処:
  ・パス決め打ちアセットの破損
    → 移動前警告、確認ダイアログ、「そのまま置く」の提供。
  ・設定ファイルの誤削除による初期化
    → README とファイル冒頭コメントで削除不可を明記。
  ・Unity バージョン差による API 挙動の違い
    → 対応目安を 2020.3 以降とし、広く使われる API に限定。
